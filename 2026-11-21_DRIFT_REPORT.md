## README.md

- The adopted-profile example says “no login, no canary” but omits `--no-canary`. [`main`](./src/index.ts#L183) passes the flags independently to [`addProfile`](./src/profile.ts#L250), which can still run a real generation canary against the adopted HOME.
- The shared-store migration prose names `agy-multi sync`; only `agy-multi profile sync` is dispatched ([`main`](./src/index.ts#L257)). The remote-login walkthrough likewise omits `--remote`, the flag that selects headless browser handling ([`addProfile`](./src/profile.ts#L275)).
- The clean-mode table overstates what one-shot `run` changes. [`runTurn`](./src/runner.ts#L40) disables slash commands and [`buildInjectedPrompt`](./src/injection.ts#L286) injects text; only the ACP path adds `--include-default-customizations=false` ([`parseAcpProxyOptions`](./src/acp/cli-args.ts)). `--system-prompt` does not replace the agent's own base instructions, and the append option also accepts literal text.
- The one-shot failover prose promises a checkpoint on every account switch. [`runWithFailover`](./src/runner.ts#L215) uses a checkpoint only for a supplied conversation ID when the attempt cannot resume it, and sends the base prompt when there is no checkpoint.
- The installation section does not distinguish PATH handling: [`install.sh`](./install.sh#L154) prints a PATH hint on POSIX, while [`install.ps1`](./install.ps1#L123) can update the persistent Windows user PATH. Both can invoke the official `agy` installer, a side effect missing from the blueprint. The scripts also use installer-specific environment variables distinct from the updater's `AGY_MULTI_REPO_SLUG` and `AGY_MULTI_GITHUB_API`.
- The installer quick-start footers still advertise the nonexistent `agy-multi use <slug>` command ([POSIX](./install.sh#L250), [Windows](./install.ps1#L193)); CLI dispatch has no `use` branch ([`main`](./src/index.ts#L124)).
- The command reference omits the `models --profile/--refresh` synopsis, `run --cwd/--json/--max-switches/--switch-delay`, `profile add --clean/--no-canary`, and ACP `--compaction-threshold` ([CLI help and dispatch](./src/index.ts), [ACP parser](./src/acp/cli-args.ts)).
- The isolation prose and diagram label settings as per-profile, but managed provisioning links selected settings, keybindings, and MCP configuration from the primary HOME ([`SHARED_ENTRIES`](./src/profile.ts#L13), [`provision`](./src/profile.ts#L206)). Adopted profiles skip provisioning, not login or canary operations.
- The `session/new` bullet attributes the initial pin to model snapshots, but [`onSessionNew`](./src/acp/server.ts#L1134) supplies no model ID to ranking and allows a quota-blocked fallback. The pool startup warning also contradicts the README's cache-only description by claiming that ranking probes every account ([`start`](./src/acp/server.ts#L214), [`rankCandidates`](./src/acp/server.ts#L825)).
- Busy-profile promotion applies only in sequential mode. If a different profile is needed mid-turn, the proxy refuses the switch rather than waiting. The switch-delay default is the same in both modes and the pacing helper has no sequential-mode guard ([`rankCandidates`](./src/acp/server.ts#L882), [`ensureChild`](./src/acp/server.ts#L714), [`paceAccountSwitch`](./src/acp/server.ts#L273)). Low quota alone does not force a handoff if no alternative can serve ([`runSessionPrompt`](./src/acp/server.ts#L1644)).
- `session/list` does not enumerate CLI conversations directly, but an external conversation loaded or resumed through the proxy can be recorded and appear in the list ([`onSessionLoad`](./src/acp/server.ts#L1203), [`onSessionList`](./src/acp/server.ts#L1357)). The ACP host guide also omits fork behavior, model-change handoffs, cancellation, and rejection of a second prompt while a turn is active ([session handlers](./src/acp/server.ts)).
- The text-only limitation is not confined to handoff: normal prompts also flatten non-text blocks to placeholders before the child call ([`promptToText`](./src/acp/prompt.ts), [`runPrompt`](./src/acp/server.ts#L1856)). The host guide omits proxy-owned `/multi-usage`, hidden auto-compaction, and bounded daemon-task continuations ([prompt handlers](./src/acp/server.ts#L1604), [`maybeAutoCompact`](./src/acp/server.ts#L1993), [`daemon-tasks.ts`](./src/acp/daemon-tasks.ts)).
- Startup awaits profile sync and can fail on provisioning errors; initialization tries at most three healthy profiles, not every available candidate ([`runAcpProxy`](./src/acp/server.ts#L2127), [`onInitialize`](./src/acp/server.ts#L1099)).

## bin/README.md

- The contract omits an install-time layout conflict: [`Install-FromSource`](./install.ps1#L111) copies both `.cmd` shims into the binary install directory, but their targets remain relative to `..\src` ([main shim](./bin/agy-multi.cmd), [ACP shim](./bin/agy-multi-acp.cmd)). The installer does not put the source tree next to that directory, so those copies are not portable installed launchers.

## src/README.md

- Managed provisioning is not uniform: `addProfile` with `clean` skips shared customization links and rules. Later sync and ACP startup call provisioning without `clean`, so those links can be added then ([`provision`](./src/profile.ts#L206), [`syncProfiles`](./src/profile.ts#L391)). The persisted profile flag still affects [`runTurn`](./src/runner.ts#L40).
- The filesystem contract leaves `<root>` undefined and omits [`resolveRoot`](./src/paths.ts#L21): it defaults to `~/.agy-multi`, honors `AGY_MULTI_ROOT`, and can rename a recognized legacy `~/.agy` directory. The side-effect list also omits macOS managed-keychain migration and deletion during reprovisioning and login ([`ensureKeychain`](./src/profile.ts#L42), [`loginProfile`](./src/profile.ts#L322)).
- The two unqualified `buildHandoffPrompt` references name different functions: ACP renders transcript text ([`prompt.ts`](./src/acp/prompt.ts#L80)); the one-shot runner renders a checkpoint ([`runner.ts`](./src/runner.ts#L117)). `rankCandidates` is a private ACP method ([`server.ts`](./src/acp/server.ts#L825)), not the exported [`rankProfiles`](./src/select.ts#L53).
- The entry-point and side-effect sections omit the runnable [`release-plan.ts`](./src/release-plan.ts#L385) CLI. `prepare --write` without `--dry-run` updates `package.json` and `CHANGELOG.md`. The subprocess inventory also omits one-shot checkpoint capture via `git rev-parse HEAD` and the updater's staged version probe ([`runner.ts`](./src/runner.ts#L111), [`installLatestRelease`](./src/update.ts#L315)).
- The interface table omits operationally relevant exports it relies on: usage/model cache accessors, `compareVersions`, `isCompiledBinary`, and `AddProfileOptions` ([`usage.ts`](./src/usage.ts), [`models.ts`](./src/models.ts), [`release-plan.ts`](./src/release-plan.ts), [`update.ts`](./src/update.ts), [`profile.ts`](./src/profile.ts)). The quota description also omits the five-hour fallback when there is no usable reset ([`runWithFailover`](./src/runner.ts#L268)).

## src/acp/README.md

- The recovery section says handoff always tries `session/resume` first and creates a child session only on failure. [`runPrompt`](./src/acp/server.ts#L1739) attempts native resume only for a cross-profile handoff with an existing child ID and no ready replacement; same-profile recovery can go straight to `session/new`, and a ready replacement can be reused. An `agent_thought_chunk` also blocks retry even if its text is empty ([`handleAgentNotification`](./src/acp/server.ts#L452)).
- The error-code summary needs to be scoped to `session/prompt`: its invalid parameters return `-32602`, but several other handlers throw ordinary errors mapped to `-32603`; prompt admission can also return `-32000` when no account can serve ([`respondFailure`](./src/acp/server.ts#L302), [`runSessionPrompt`](./src/acp/server.ts#L1604)).
- The RPC inventory omits material behavior: [`onSessionFork`](./src/acp/server.ts#L1414) requires an in-memory session and gives the fork a fresh proxy ID; [`onSessionList`](./src/acp/server.ts#L1357) filters by exact `cwd` and paginates 100 records at a time, including closed records; [`onSessionClose`](./src/acp/server.ts#L1380) calls the child only for a live, loaded session and tolerates `-32601` only for delete. Closing retains the record and does not prevent later prompts.
- The model and prompt sections omit that model changes are intercepted for `session/set_model` and model-specific `session/set_config_option`; empty-history sessions can move immediately, whereas history-bearing sessions defer the move ([`handleModelChangeRequest`](./src/acp/server.ts#L1478)). [`mergeSessionModelsResult`](./src/acp/server.ts#L1000) also merges healthy cached catalogs and reasoning metadata. The child prompt is a single text block, not the full client payload ([`promptToText`](./src/acp/prompt.ts), [`runPrompt`](./src/acp/server.ts#L1856)).
- Unknown IDs take the same adoption path for `session/resume` as for `session/load`. [`onSessionLoad`](./src/acp/server.ts#L1203) checks conversation-file ownership before ranking a fallback profile; on a load, returned chunks can hydrate an empty transcript ([`trackLoadChunk`](./src/acp/server.ts#L2059)).
- The transport inventory leaves out [`AcpChild.respondError`, `alive`, and `initialized`](./src/acp/child.ts), and [`handleClientNotification`](./src/acp/server.ts#L376) also routes ordinary notifications to the owning child or control child, not just `session/cancel`.
- The 25-second temporary-directory model probe is specifically [`syncProfileModelReasoning`](./src/acp/model-reasoning.ts). The proxy's normal model refresh uses [`fetchModels`](./src/models.ts#L258) through `ProbeSync`, with a different timeout and no temporary working directory.
- `session/new` can consider quota-blocked fallback candidates and persist classified setup failures; the “three ranked candidates” summary alone omits both effects ([`onSessionNew`](./src/acp/server.ts#L1134)).
